## 📝 Project Summary

**Description:**
The **Cyber Demonstration Portal** is an interactive "Hack and Patch" web application designed for educational purposes. It provides a side-by-side interface for demonstrating cyber attacks alongside their secure code mitigations.

**Security Concepts Implemented:**
- **SQL Injection (SQLi):** Implemented a vulnerable authentication mechanism using string formatting to demonstrate query manipulation (`' OR '1'='1' --`), followed by a secure implementation using SQLite Parameterized Queries.
- **Cross-Site Scripting (XSS):** Created a vulnerable search function using Flask's `Markup()` to reflect scripts into the DOM without escaping, paired with a secure implementation relying on Jinja2's context-aware auto-escaping.
- **Insecure Direct Object Reference (IDOR):** Demonstrated data exposure by fetching transaction statements solely via user-provided IDs (`?target=1`). The secure fix implements backend session validation to ensure authorization.
- **Broken Business Logic:** Simulated a wire transfer where a hidden HTML `from_account` field can be maliciously modified by the client to steal funds. Mitigated by enforcing server-side state (the secure session) as the single source of truth.

## 📝 Project Description

The Cyber Demonstration Portal is an interactive "Hack and Patch" web application designed for educational purposes. It addresses the lack of visual, side-by-side learning tools for web vulnerabilities by providing a platform where users can safely execute common cyber attacks on a vulnerable application state. It then immediately demonstrates the secure coding practices and proper backend configurations required to mitigate those exact attacks, thereby closing the loop between exploitation and remediation.

---

## 🔐 Security Concepts Implemented

- **SQL Injection Prevention:** Implemented Parameterized Queries (`"SELECT * FROM users WHERE username=?"`) to automatically safely escape inputs and prevent malicious SQL logic manipulation.
- **Cross-Site Scripting (XSS) Mitigation:** Leveraged Context-Aware Auto-Escaping via the Jinja2 templating engine to sanitize user inputs reflecting in the DOM.
- **Insecure Direct Object Reference (IDOR) Protection:** Enforced strict server-side Access Control list validations to ensure the requested resource ID belongs to the cryptographically authenticated user session.
- **Secure Business Logic:** Enforced server-side state authority over client-supplied hidden parameters to stop unauthorized fund transfers resulting from form tampering.
